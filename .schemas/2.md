# Generate Character Metadata From URL

Production-grade README for the Perchance generator `generate-character-metadata-from-url`.

This generator accepts one or more source URLs, extracts character-related information from each page, maps the extracted data into a selected schema, validates the result, and outputs downloadable JSON metadata. The generator is designed around Perchance's plugin import model and generator structure, including plugin-style imports such as `{import:plugin-name}`. [perchance.fandom](https://perchance.fandom.com/wiki/Importing_and_Exporting)

## Features

- Multi-URL ingestion, including single URLs, comma-separated URLs, and queued URL lists. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Selectable output schema, supporting both a standard and NSFW metadata format. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Structured JSON generation for each processed character record. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Combined batch output under a top-level `character` array when multiple URLs are processed. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Optional in-browser JSON editing before export. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Downloadable `.json` export for downstream workflows. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Optional validation output for field-level schema checks. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Extensible scraping pipeline with site-specific handlers and generic fallback extraction. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Optional AI-assisted inference for missing or weakly supported fields. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Optional progress reporting for multi-URL batch jobs. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Generator Name

`generate-character-metadata-from-url`

## Purpose

The generator converts semi-structured or unstructured web content into strongly structured character metadata. It is intended for workflows where users want consistent JSON objects that can be reused in character tools, AI pipelines, content archives, or downstream schema-driven applications. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Supported Schemas

The generator exposes a **Schema Type** selector with two values: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

| UI Value | Target Schema | Purpose |
|---|---|---|
| `normal` | `ultra-detailed-character-metadata-v2.schema.json` | General character metadata. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics) |

The selected schema determines the output shape and the validation rules that should be applied before the JSON is written to the output panel. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Architecture

The generator is easiest to maintain when it is treated as a staged pipeline with clear boundaries between input parsing, content retrieval, extraction, mapping, validation, and output rendering. This separation keeps scraper logic independent from schema logic and makes site support easier to extend over time. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Core layers

1. **Input layer** — parses the selected schema and normalizes user-entered URLs. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
2. **Fetch layer** — retrieves remote page content for each URL, typically via `superFetch`. [perchance](https://perchance.org/super-fetch-plugin)
3. **Extraction layer** — routes the HTML through site-specific scrapers or a generic fallback extractor. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
4. **Mapping layer** — converts raw parsed fields into the exact selected schema structure. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
5. **Validation layer** — checks required fields, basic types, and schema-specific constraints before output. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
6. **Presentation layer** — renders pretty-printed JSON, optional validation messages, and download-ready content. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Processing model

A clean conceptual architecture looks like this: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

```text
User Input
  -> URL Parsing
  -> Fetch HTML
  -> Detect Source Type
  -> Extract Character Data
  -> Map To Selected Schema
  -> Validate Output
  -> Render JSON
  -> Download JSON
```

## Data Flow

The generator should process each URL independently, then merge all resulting objects into a single output payload. This avoids cross-source contamination and makes batch jobs easier to debug when one source fails or validates poorly. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### End-to-end flow

1. Read `schema_type`. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
2. Split `url_input` by commas, trim whitespace, and discard empty items. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
3. For each URL, fetch the page HTML. [perchance](https://perchance.org/super-fetch-plugin)
4. Detect whether the source matches a supported site pattern such as Fandom, Wikipedia, AO3, or a generic page. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
5. Extract raw character fields from the page. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
6. Map extracted values into the selected schema. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
7. Optionally enrich missing values with inference logic. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
8. Validate the mapped object. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
9. Push the result into the `character` array. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
10. Serialize the final object into formatted JSON and assign it to `json_output`. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Core loop

```js
urls = url_input.split(",").map(u => u.trim()).filter(u => u.length > 0);

schema = schema_type;
characters = [];

for (url of urls) {
  html = superFetch(url);
  parsed = scrapeCharacterFromHTML(html);
  mapped = mapToSchema(parsed, schema);
  characters.push(mapped);
}

json_output = JSON.stringify(
  { character: characters },
  null,
  2
);
```

### Output contract

The output should be consistently described as a JSON object with a `character` array, even for a single processed URL. This is more stable than switching between object and array modes depending on input count. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

```json
{
  "character": [
    {
      "identity": {},

```

## Scraping Strategy

The extraction layer should prefer deterministic site-specific scrapers first and use generic extraction only as a fallback. That gives better field quality on structured sources while preserving broad compatibility for arbitrary pages. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Router

```js
function scrapeCharacterFromHTML(html) {
  doc = parseHTML(html);

  if (isFandomWiki(doc)) return scrapeFandom(doc);
  if (isWikipedia(doc)) return scrapeWikipedia(doc);
  if (isAO3(doc)) return scrapeAO3(doc);
  if (isCharacterCard(doc)) return scrapeCard(doc);

  readable = extractReadableContent(doc);
  return scrapeGeneric(readable);
}
```

### Site-specific handlers

- **Fandom / wiki sources** can usually provide names, aliases, species, gender, age, relationships, and infobox-oriented metadata. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- **Wikipedia sources** are usually stronger for summary text and broad descriptive context than deep field coverage. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- **AO3 sources** are useful for fandom tags, relationships, and summary-style narrative context. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- **Generic sources** should rely on heuristic extraction, keyword analysis, and defensive defaults. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Schema Mapping

Mapping should be isolated behind a dispatcher so schema differences are handled in one place rather than leaking into the scraper layer. This makes it easier to add schema versions later without rewriting extraction logic. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Dispatcher

```js
function mapToSchema(p, schema) {
  if (schema === "nsfw") return mapToNSFWSchema(p);
  return mapToNormalSchema(p);
}
```

### Normal schema sections

The standard schema should populate these major groups, defaulting unsupported fields safely instead of omitting required branches: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

- `identity`
- `appearance`
- `personality`
- `background`
- `skills`
- `relationships`
- `equipment`
- `meta`
- `physiology`
- `psychology`
- `game_stats`
- `misc`

### NSFW schema extension

The NSFW schema should build on the normal schema and add an `nsfw` branch rather than duplicating the entire mapping strategy. The supplied design models `nsfw` as an array containing one object with relationship, preference, health, explicit-content, fluid, and consent-related fields. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Validation Rules

Validation should run after mapping and before the final JSON is written. A lightweight validator is enough for immediate UI feedback, while a stricter schema validator can be added later if needed. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Minimum validation scope

Validation should check at least the following: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

- Required branch presence, such as `identity` and `appearance`.
- Required field presence, especially `identity.name`.
- Basic type checks, such as string and array expectations.
- NSFW-only requirements when `schema_type` is `nsfw`.
- Structural integrity of the final output object before serialization.

### Example validator

```js
function validateCharacter(c, schema) {
  const errors = [];

  if (!c.identity || !c.identity.name || c.identity.name.trim() === "") {
    errors.push("identity.name is required");
  }

  if (!c.appearance || typeof c.appearance.species !== "string") {
    errors.push("appearance.species must be a string");
  }

  if (schema === "nsfw") {
    if (!Array.isArray(c.nsfw) || c.nsfw.length === 0) {
      errors.push("nsfw array must exist and contain at least one entry");
    } else {
      const n = c.nsfw[0];
      if (!n.sexual_orientation) {
        errors.push("nsfw[0].sexual_orientation is required");
      }
    }
  }

  return {
    valid: errors.length === 0,
    errors
  };
}
```

### Validation reporting

Validation errors should be collected per processed character and surfaced in a readable panel rather than silently failing. This is especially useful in batch mode, where a subset of URLs may succeed while others produce weak or invalid output. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

```js
validation_results = [];

for (i = 0; i < characters.length; i++) {
  const result = validateCharacter(characters[i], schema);
  validation_results.push({ index: i, ...result });
}

if (show_validation) {
  validation_output = validation_results
    .map(r => `Character #${r.index + 1}:\n` +
              (r.valid ? "  ✔ Valid\n" :
                         "  ✖ Invalid\n" +
                         r.errors.map(e => "    - " + e).join("\n")))
    .join("\n\n");
}
```

## Optional Enhancements

These features fit the current design without changing the base responsibilities of the generator: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### AI field inference

AI-assisted inference can fill sparse fields such as archetype, moral alignment, genre, themes, or combat style by deriving signals from scraped background text, appearance descriptions, and tags. This is best treated as enrichment, not authoritative extraction. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Avatar post-processing

Avatar URLs can be post-processed through a face-detection and crop step before schema mapping. That can improve consistency for downstream portrait-oriented consumers, but it depends on an external service or plugin-like integration. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

### Progress UI

Sequential batch processing makes progress reporting straightforward. A progress label and percentage field help users understand that the generator is still working during long multi-URL jobs. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Known Limitations

The current specification is strong as a product concept, but several implementation risks should be documented clearly so users and contributors know what to expect. [perchance](https://perchance.org/super-fetch-plugin)

- Web pages vary widely in structure, so extraction quality will differ between sources. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Generic fallback scraping is inherently less reliable than structured wiki-style scraping. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Some pages may block fetching, rate-limit requests, or load content dynamically in ways that simple HTML retrieval cannot fully capture. [perchance](https://perchance.org/super-fetch-plugin)
- Schema-complete output does not guarantee factually complete output, because many fields may need defaults when source material is sparse. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- AI-assisted inference can improve completeness, but inferred values may be plausible rather than source-grounded. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- NSFW schema generation requires careful content controls and may not be appropriate for all source material or deployment contexts. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Avatar face-cropping depends on an external face-processing service and is not self-contained in the current design. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
- Validation examples shown here are lightweight checks, not full JSON Schema enforcement. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Recommended Implementation Notes

A production implementation should keep the extractor, mapper, validator, and UI state updates loosely coupled. That makes the generator easier to test, easier to extend with new source handlers, and less fragile when schema revisions occur. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

Two consistency rules matter most in the final implementation. First, always emit a single top-level object with `character` as an array so downstream consumers do not have to special-case single-item outputs. Second, keep inferred or guessed values distinguishable in the internal pipeline, even if they are serialized normally, so future versions can expose provenance or confidence scoring. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Development Guidance

A clean implementation should favor deterministic extraction where possible, defensive defaults where extraction is weak, and transparent validation output whenever assumptions fail. That balance will make the generator more trustworthy than a design that silently hallucinates completeness from sparse pages. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)
