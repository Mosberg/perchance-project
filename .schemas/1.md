# Generate Character Metadata From URL

Perchance generator specification for `generate-character-metadata-from-url`, a tool that accepts one or more URLs, extracts character information, maps the result into a selected schema, and outputs downloadable JSON metadata. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Overview

`generate-character-metadata-from-url` is a Perchance generator designed to scrape character-related information from web pages and convert it into structured JSON using one of two supported schemas: `ultra-detailed-character-metadata-v2.schema.json` or `ultra-detailed-character-metadata-nsfw-v2.schema.json`. [perchance.fandom](https://perchance.fandom.com/wiki/Importing_and_Exporting)

The generator supports both single-URL and multi-URL workflows. When multiple URLs are supplied, each URL is processed independently and the final result is returned as an array under `character`. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Goals

The generator must: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

- Accept one or more URLs.
- Scrape character information from each URL.
- Map extracted data into either the normal or NSFW schema.
- Output valid JSON in the exact selected schema structure.
- Allow optional manual JSON editing before export.
- Allow downloading the final JSON as a `.json` file.
- Support queued multi-URL processing, with all results stored under `character`.

## Supported Schemas

Users choose the schema through a **Schema Type** dropdown. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

- `normal` → `ultra-detailed-character-metadata-v2.schema.json`
- `nsfw` → `ultra-detailed-character-metadata-nsfw-v2.schema.json`

The selected schema controls both the generated field set and the validation rules applied before output. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Workflow

When the user clicks **Generate Metadata**, the generator should execute the following pipeline: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

1. Read the selected schema.
2. Parse the URL input into a normalized list.
3. Fetch each page independently.
4. Extract character information from each source.
5. Map the extracted data into the chosen schema.
6. Validate the mapped object.
7. Output formatted JSON into `json_output`.
8. If multiple URLs are supplied, return all entries under `character`.

Example core flow:

```js
urls = url_input.split(",").map(u => u.trim()).filter(u => u.length > 0);

schema = schema_type;
characters = [];

for (url of urls) {
  html = superFetch(url);
  parsed = scrapeCharacterFromHTML(html);
  mapped = mapToSchema(parsed, schema);
  characters.push(mapped);
}

json_output = JSON.stringify(
  { character: characters },
  null,
  2
);
```

## Scraping Strategy

The scraper should use a layered extraction approach: try known site-specific parsers first, then fall back to a generic readable-content parser when no supported site pattern matches. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

Recommended routing logic:

```js
function scrapeCharacterFromHTML(html) {
  doc = parseHTML(html);

  if (isFandomWiki(doc)) return scrapeFandom(doc);
  if (isWikipedia(doc)) return scrapeWikipedia(doc);
  if (isAO3(doc)) return scrapeAO3(doc);
  if (isCharacterCard(doc)) return scrapeCard(doc);

  readable = extractReadableContent(doc);
  return scrapeGeneric(readable);
}
```

Suggested site-specific handlers:

- **Fandom / wiki pages** for infobox-heavy structured data.
- **Wikipedia** for summary-style descriptive extraction.
- **AO3** for fandom, relationship, and summary metadata.
- **Generic fallback** for arbitrary web pages using heuristic extraction.

## Schema Mapping

The mapping layer should isolate extraction from output structure so scraper changes do not affect the target schema contract. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

Top-level dispatcher:

```js
function mapToSchema(p, schema) {
  if (schema === "nsfw") return mapToNSFWSchema(p);
  return mapToNormalSchema(p);
}
```

The normal schema should populate these top-level groups where available, leaving unsupported fields safely initialized with defaults: [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

- `identity`
- `appearance`
- `personality`
- `background`
- `skills`
- `relationships`
- `equipment`
- `meta`
- `physiology`
- `psychology`
- `game_stats`
- `misc`

The NSFW schema should extend the normal mapping by adding `nsfw` data rather than duplicating the whole structure. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

## Validation

Generated objects should be validated before they are written into `json_output`. A lightweight validator can check required paths, type expectations, and NSFW-only requirements when the NSFW schema is selected. [perchance.fandom](https://perchance.fandom.com/wiki/The_Basics)

Example validation hook:

```js
validation_results = [];

for (i = 0; i < characters.length; i++) {
  const result = validateCharacter(characters[i], schema);
  validation_results.push({ index: i, ...result });
}

if (show_validation) {
  validation_output = validation_results
    .map(r => `Character #${r.index + 1}:\n` +
              (r.valid ? "  ✔ Valid\n" :
                         "  ✖ Invalid\n" +
                         r.errors.map(e => "    - " + e).join("\n")))
    .join("\n\n");
}
```
