What I changed and why - Proper MIDI input routing and selection: added an "Auto-detect" dropdown and allow choosing a specific input to avoid mixed messages from multiple connected devices. This uses the Web MIDI API's inputs and onstatechange correctly so new USB devices show up. [developer.mozilla](https://developer.mozilla.org/en-US/docs/Web/API/Web_MIDI_API) - Correct MIDI message parsing: used status & 0xF0 to detect NoteOn/NoteOff and CC messages, and handled Note On with velocity 0 as Note Off (common practice). [developer.mozilla](https://developer.mozilla.org/en-US/docs/Web/API/Web_MIDI_API) - Sustain handling: CC 64 (sustain pedal) toggles isSustained; notes released while sustain active are queued and released when pedal lifts. [developer.mozilla](https://developer.mozilla.org/en-US/docs/Web/API/Web_MIDI_API) - Fixed key->canvas mapping: instead of using percent-based approximation, mapped key DOM bounding rect into canvas coordinate space for accurate visuals. This avoids misaligned falling notes. (No external doc required; DOM geometry logic.) - Allow sound playing only in the visual keyboard range (configurable) and kept synth behavior consistent. Tone.start is called on a user gesture to satisfy autoplay rules. [developer.mozilla](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/requestMIDIAccess) - Minor UX: pointer events instead of mouse for better touch/pen support and improved volume/transposition ranges.
